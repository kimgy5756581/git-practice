## 1. 가장 크게 배운 것 — 근거의 유형이 결과를 가른다

같은 사람이 같은 파이프라인에서 낸 판단인데도, **근거가 어디서
왔는지에 따라 성적이 극단적으로 갈렸다.**

| 근거 유형 | 전적 | 비고 |
|---|---|---|
| **리더보드 2점 역산** | **8전 8승** | TARGET 예측 1140.38 → 실측 1140.3834 (오차 0.003) |
| **2024 기반 정량 계산** | **0전 3패** | 3번 중 2번은 **방향까지 반대** |
| 시드간 산포 지표 | 6전 6승 (정보 변경) | 정규화 계열에서는 무효 |
| R² 선별기 | R²≥0.64 정확 / R²≤0.46 무의미 | |

### 왜 2024 계산이 전부 실패했나

우리 파이프라인은 **2019~2024 전체로 학습하고 2024로 검증**했다.
모델이 2024를 부분적으로 외운 상태라 in-sample 지표가 최대 250배까지
부풀려졌고, 그 위에서 잰 모든 통계가 오염됐다.

```
그룹 잔차        외워서 거의 0      → "보정이 필요 없다"고 보임
UNK 상대위치     그 투수들을 외움    → 실제보다 잘 맞음
분산 분해        노이즈가 사라짐     → 노이즈를 과소평가
                                    → k* 를 231~806 으로 계산
                                    → 실제 최적은 10  (−11.4 손실)
```

**노이즈를 과소평가하니 "더 믿어라"가 나왔고, 정답은 늘 그 반대였다.**
세 번 다 같은 메커니즘이었는데 세 번째까지 눈치채지 못했다.

### 규칙으로 굳힌 것

```
❌ 오염된 검증셋의 계산으로 상수를 "확정"하지 않는다
△ 그런 계산은 프로브 방향 후보로만 쓴다.  "확실하다"는 말은 금지
✅ 값의 확정은 out-of-sample 채점기(리더보드)로만 한다
```

## 2. 핵심 도구 — 리더보드 포물선 역산

### 원리

Brier Skill Score 는 예측의 이차함수다. 앵커에서 방향 Δ 로 θ 만큼
움직이면 점수는 다음과 같이 변한다.

```
Score(θ) = S + b·θ − C·θ²

  S = 앵커 점수 (이미 앎)
  C = K_BSS · E[Δ²]          ← 로컬에서 정확히 계산 가능
  b = 미지수 (기울기)         ← 제출 1발로 역산
```

### 절차

```
1.  후보를 만들고 로컬에서 C 를 계산한다        (제출 0발)
2.  θ=1 을 한 발 제출해 실측 점수를 얻는다
3.  b = obs − S + C
4.  꼭짓점 θ* = b / (2C),  최대이득 = b²/(4C)
5.  θ* 가 1 근처면 그 제출본이 곧 최적 → 추가 제출 불필요
```

### 이 도구의 강점

- **하방이 계산된다.** `S − C` 아래로는 못 내려간다. 도박이 아니다.
- **져도 정보가 남는다.** b 의 부호를 알면 반대 방향이 열린다.
  실제로 `k` 축은 첫 시도가 −11.4 였고, 그 부호를 보고 반대로 밀어
  **+10.64** 를 얻었다.
- **검증셋이 필요 없다.** 리더보드가 곧 out-of-sample 채점기다.

### 한계

- **하루 5발.** 탐색까지 여기에 의존하면 발이 순식간에 마른다.
- **비선형 축에는 안 통한다.** 클립·포화가 있으면 외삽이 어긋난다.
  (2층 시프트 클립 때문에 θ=1.5 예측이 빗나갔다)

## 3. 두 번째로 크게 배운 것 — 값이 아니라 **형태**를 의심하라

대회 후반의 이득은 대부분 **"이 상수는 왜 이 모양이지?"** 에서 나왔다.

| 발견 | 원래 형태 | 바꾼 형태 | 이득 |
|---|---|---|---|
| **k** | 평활상수 50 (근거 없이 정함) | 10 | **+10.64** |
| **a** | 로짓 배율 **하나** (대칭) | + 2차항 q | **+1.05** |
| **그룹 타깃** | 2024 비율을 **100% 반영** | 수축 0.872 / 0.839 | **+2.29** |

### 공통 구조

세 가지 모두 **"노이즈 낀 추정치를 얼마나 믿을까"** 였고,
전부 **덜 믿는 쪽**이 정답이었다.

```
k = 50   →  시즌 표본을 과신
a 배율만 →  보정 곡선이 직선이라고 가정
수축 1.0 →  2024 그룹 차이를 그대로 신뢰
```

### 왜 늦게 발견했나

`k=50`, `MIN_CNT=100`, `N_BINS=48`, `CLIP2=0.012` 같은 값은
파이프라인 초기에 **"일단 이 정도로"** 정해놓고 한 번도 다시 보지 않았다.
**성능이 오를수록 이런 초기 임의값이 병목이 된다.**

다음 대회에서는 시작할 때 이 목록부터 만들어야 한다.

```
"근거 없이 정한 값" 목록  →  성능이 정체될 때마다 위에서부터 프로브
```

## 4. 세 번째 — 분포 정합은 "비율 맞추기"가 아니다

test 의 21% 가 pid 미등록(2025 신인)인데 train 은 0.68% 뿐이었다.
**30배 과소 노출**이라 모델이 "모르는 투수" 상황을 사실상 안 배웠다.

그래서 학습 중 `p = 0.21` 확률로 pid 임베딩을 지웠다 (도메인 랜덤화).

```
결과:  −3.25 (패)
       그런데 b = +4.42 로 ★방향은 맞았음★
       θ* = 0.29  →  최적 p ≈ ★0.06★
```

### 왜 21% 가 과했나

```
많이 가리면  →  없는 상황엔 강해지지만
                ★있는 상황에서 그 피처를 덜 믿게 됨★
```

`C` 를 분해해보니 변화의 **70% 가 known 행**에서 나왔다.
`pid_emb` 은 기여 +40 의 최강 피처인데, 5번 중 1번 가리니
있을 때조차 덜 신뢰하게 된 것이다.

**교훈: 분포 정합의 최적점은 test 비율이 아니라 그보다 훨씬 낮다.**
같은 논리가 트랙맨 `keep_rate` 에도 적용될 수 있었는데 확인하지 못했다.

## 5. 지표의 유효 범위

### 시드간 산포 (4시드 예측의 평균 대비 rms)

정보를 바꾸는 실험에서 **6전 6승**이었다.

```
sf3   0.007407 개선 → +6.39 승
sfl   0.007211 개선 → +11.24 승
sf6/sfm/sfn/sfk  악화 → 전부 패
```

**그런데 dropout 에서 깨졌다.** 산포는 역대 최저(0.006766)였는데 졌다.

```
정보 개선  →  모델이 데이터로 더 결정됨 → 일치↑  ★그리고★ 정확도↑
정규화     →  강제로 단순해짐          → 일치↑  ★그러나★ 정확도↓
```

**지표는 "무엇을 바꿨는지"에 따라 해석이 달라진다.**

### R² 선별기

후보의 예측 변화를 과거 실험 방향들로 회귀해 설명력을 본다.

```
R² ≥ 0.64  →  예측 정확.  실제로 seed8 은 예측대로 패
R² ≤ 0.46  →  ★새로운 방향★.  예측 무의미
              sf3(0.313) · sfl(0.057) · shrink(0.017) 전부 여기서 승
```

**R² 가 낮다는 건 "모른다"는 뜻이고, 그건 쏴봐야 안다는 신호다.**

## 6. 판단에 대한 반성

### 내(모델) 판단 기록

```
❌ "SWA-A 하지 마"     →  +9.42
❌ "sf3 비추천"        →  +6.39
❌ "k 축 접자"         →  +11.24
❌ "s_unk 5.2σ 확실"   →  −2.89
```

세 번은 **이기는 걸 말렸고**, 한 번은 **틀린 확신을 붙여 발을 날렸다.**
이를 뒤집은 건 전부 사용자의 반문이었다.

```
"k=20 일 수도 있잖아"
"니가 접자니까 오히려 신뢰가 간다"
"shrink 해보자"
```

### 교훈

```
① 기계적 절차(포물선 역산)는 8/8, 직관적 판단은 3승 4패
   → ★절차를 신뢰하고 직관은 의심하라★
② "확실하다"는 말은 근거 유형을 밝힌 뒤에만
   "2024 표본 안에서 5.2σ" ≠ "test 로 전이된다"
③ R² 가 낮으면 예측을 포기하고 쏴야 한다.
   낮은 R² 에서 내린 예측은 ±10 씩 빗나갔다
```

## 7. 자동화에 대하여

상위권 팀 중 한 곳은 Claude Code 로 **실험 루프를 백그라운드 자동화**하고,
로그 대신 **md 요약본을 참조**해 토큰을 절약했다고 밝혔다.

우리와의 차이를 정직하게 보면:

```
제출 횟수      차이 없음 (양쪽 다 매일 소진)
GPU 실험 수    ★차이 큼★.  우리는 TabM 학습을 8~10회, 자동화면 수십 회
맥락 유지      ★차이 큼★.  우리는 대화 압축으로 세부가 날아간 적이 있음
```

### 다만 GPU 만 늘린다고 해결되지 않는다

```
후보 50개를 학습해도  →  고르려면 제출 1발씩  →  하루 5발
= ★평가가 병목★.  GPU 는 후보만 만든다
```

**GPU 의 진짜 값어치는 후보 생산이 아니라 "검증 구조를 만들 시간"이었다.**
우리는 TabM 하니스 검증(2.5시간)이 아까워 LGB로 대충 했고,
그 결과 0/4 가 나와 하니스를 폐기했다. **순서가 거꾸로였다.**

### 그리고 이득의 3분의 2는 GPU 없이 나왔다

```
GPU 재학습 필요:  +28.4  (33%)   SWA-A · k=10 · sf3 · recent23
후처리 (GPU 0~5분): +58.9  (67%)   TARGET · a · t · 수축 · q · s_unk …
```

**후처리 축은 값싸고, 그런데도 오래 방치돼 있었다.**

## 8. 다음 대회 체크리스트

우선순위 순.

```
1. ★검증 구조를 가장 먼저 만든다★
   · 검증 연도를 학습에서 제외한다 (시계열이면 필수)
   · 그 검증셋이 test 상황을 재현하는지 확인한다
     (UNK 비율 · 평균 드리프트 · 규제 변경 여부)
   · 리더보드로 확인된 사실이 쌓일 때마다 ★하니스와 대조★ 해
     신뢰도를 측정하고, 확인된 만큼만 "거르기" 용도로 쓴다
   · 반드시 ★최종 모델과 같은 종류★ 로 검증한다 (LGB 로 TabM 을 대신 못 함)

2. ★"근거 없이 정한 값" 목록을 처음부터 만든다★
   평활상수 · 임계값 · 구간 수 · 마스킹 비율 · 보정 함수의 형태
   성능이 정체될 때마다 위에서부터 프로브

3. ★값이 아니라 형태를 의심한다★
   "배율 하나면 충분한가" · "선형이어야 하나" · "100% 반영해야 하나"

4. ★리더보드는 확인용, CV 는 탐색용★
   역할이 다르다. CV 가 없으면 탐색까지 리더보드로 하게 되고
   발당 노이즈 수준(0.407)의 도박을 반복하게 된다

5. ★실험 루프를 자동화하고 결과는 md 로 누적한다★
   로그 원문을 맥락에 올리지 않는다

6. ★주장에는 근거 유형을 붙인다★
   "리더보드 실측" / "오염된 검증셋 계산" / "추측"
```

기록해두는 이유: **실패한 방향을 다시 시도하지 않기 위해서,
